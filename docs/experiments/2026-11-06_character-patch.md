# Патч персонажей: переписанный этап и стиль ссылок

**Дата:** 2026-11-06
**Ветка:** `experiment/deepseek-deepinfra`
**Модель:** `deepseek/deepseek-v4.1-flash-1017`, DeepInfra `fp8`, reasoning по умолчанию
**Данные:** «Монолог фармацевта» (LN), том 1, главы 0–8. Базовая копия `kusuriya-no-hitorigoto__charbase`: персонажей нет, саммари 9 глав (стоили $0.005), одинаковые для всех прогонов.
**Сырые данные:** `logs/experiments/patch/` (`char_*.log`, скрипт `char_run.py`), результаты в `output/kusuriya-no-hitorigoto__char_*/project.db`

## Что было не так в старом патче

- Описание персонажа одно на всю книгу и перезаписывается: послушать главу 3 с описанием из главы 30 — спойлер.
- Модели давали UUID персонажей; она их портила (в прогоне `char_old` — `uuid_parsing`, патч главы потерян).
- Модель могла патчить любого персонажа из справочника, а не только тех, кто в главе.

## Что изменилось

- `description_timeline[chapter_id]`: при новом раскрытии модель пишет полное описание на 2–4 предложения «на момент этой главы», без знания будущего. Спойлер-фри по построению.
- Вместо UUID — короткие ссылки (`c1`, `c2`… или имя, см. ниже). Патчи вне пачки и выдуманные ref отбрасываются и считаются в статистике.
- Один проход по известным + кандидатам пачками по `character_patch_batch` (8).
- `visual_base` / `voice_base` пишутся только если пусты; переименование только на «более полное» имя (не «Джинши» → «Евнух Джинши»).
- **Векторный дедупликатор больше не сливает** (см. результаты), только логирует сходство.

## Результаты

### Первый круг (векторное слияние включено, порог 0.70)

| Прогон | Персонажей | $ | Время | Ошибки валидации |
|---|---|---|---|---|
| `char_old` (старый код) | 9 | 0.0411 | 1178 с | 1 (битый UUID) |
| `char_new_c` (ref `c1`) | 6 | 0.0210 | 664 с | 0 |
| `char_new_n` (ref по имени) | 8 | 0.0244 | 716 с | 0 |

Векторный дедупликатор, который в старом коде не срабатывал ни разу, в новом сработал 4 раза — **все 4 слияния ошибочные**:

| Кандидат | Слит с | Сходство |
|---|---|---|
| Гёкуё | Рифа | 0.744 |
| Хоннян | Маомао | 0.760 |
| Линли | Гёкуё | 0.703 |
| Император | Джинши | 0.760 |

Причина: теперь кандидат сравнивается по имени + описанию, а в одном сеттинге (задний дворец) описания разных людей похожи на 0.70–0.76. Последствия: у Рифы алиасы «Гёкуё», «Линли»; версия описания Джинши за главу 8 — описание императора.

Решение: сходство только логируется (`vector_similar_not_merged`). Дубли ловят ref от модели и сопоставление по имени/алиасам/имени без титулов.

### Второй круг (без векторного слияния)

| Прогон | Персонажей | $ | Время | Версий описаний | Ошибки |
|---|---|---|---|---|---|
| `char_new_c2` (ref `c1`) | 9 | 0.0220 | 660 с | 32 | 0 |
| `char_new_n2` (ref по имени) | 9 | 0.0191 | 590 с | 29 | 0 |

- Состав совпадает со старым кодом (Маомао, Джинши, Гаошун, Гёкуё, Линли, Рифа, Сяолан, Фуё, Хоннян), ложных слияний нет. Векторное сходство снова было выше порога у тех же пар (0.73–0.76) — без отключения они бы склеились.
- Ни одного выдуманного/неизвестного ref и ни одного патча вне пачки ни в одном из 4 новых прогонов.
- Описания растут по главам. Джинши: гл. 3 «чиновник, расследования» → гл. 5 «красивый евнух, нашел Маомао по ткани» → гл. 8 «император сделал его мерилом при выборе супруг». Того, кем он окажется, в описаниях нет.
- Император во втором круге не создан ни в одном прогоне: разведка не выдала его кандидатом — разброс модели, не стиль ссылок.

### Стиль ссылок: `c1` против имени

Разницы в качестве не видно: одинаковый состав, 0 ошибок ref в обоих. По цене стили поменялись местами между кругами (0.021/0.024 → 0.022/0.019) — это шум. Ссылки по имени удобнее читать в логах и промптах при отладке.

## Итог

- Новый патч в ~2 раза дешевле и быстрее старого, без ошибок валидации, с версиями описаний по главам.
- Автослияние по векторам выключено. Совпадение личностей (например, Шисуи — Лоулан) — не дубль, а раскрытие сюжета: планируется связь `identity_links` с главой раскрытия и подтверждением человеком, а не слияние.

## Оговорки

- 9 глав одной книги, по 2 прогона на стиль.
- Алиасы стали беднее старых (старый код писал имя в алиасы самого себя и титулы вроде «помощник Джинши»); встречается алиас-роль «средняя наложница четвертого ранга».
- Описания по главам пока никто не читает: сценарий и API используют `description`. Это следующий шаг.
